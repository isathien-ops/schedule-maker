# Контракт данных

Для разработчика, который видит проект впервые: какие данные хранит и передаёт программа «Расписание занятий» (файлы проекта, вход и выход движка `solve.exe`, HTTP API страницы) и какой код за что отвечает.

Всё сверено с текущим кодом. Где поведение неочевидно, оно проверено запуском через тестовый клиент Flask на временной копии проекта: `SCHEDULE_DATA_DIR` указывал на временную папку, в неё импортирован `Расписание_2026-27.zip`, затем шли сборка этапа «Поток 2» (2 варианта, 100 000 шагов), просмотр вариантов, принятие и все выгрузки. «Сегодня» при проверке — 05.10.2026.

Ссылки идут на **модули и функции, а не на номера строк**: код ещё дочищают, и функции могут переименовать. Если имя функции не находится, ищите по модулю.

Где искать устройство кода:

| что | где описано |
|---|---|
| предметный слой, карта модулей и слоёв | шапка `src/modules/functions/__init__.py` |
| данные проекта, разделы и этапы | шапка `src/modules/functions/model.py` |
| сервер, карта модулей; правило имён с «_» (внутренний шаг модуля: `build._runSolver` и т. п.) | шапка `src/web/server.py` |
| протокол действий | шапка `src/web/actions.py` |
| вкладки сервер ↔ страница | шапка `src/web/tabs/__init__.py` |
| движок, вход и выход | шапка `src/modules/solve.cpp` |

## 1. Где лежат данные

### 1.1. Папка данных

Путь задаёт `src/variables.py`:

```
PATH_TO_FOLDER = <getAppDataDir()>/Schedule-Maker-1
PROJECTS_DIR   = PATH_TO_FOLDER/projects
```

`getAppDataDir()` берёт первое, что найдёт:
1. переменную окружения `SCHEDULE_DATA_DIR` (`DATA_DIR_VARIABLE`), если она задана и не пуста;
2. `%APPDATA%`, если она задана;
3. иначе текущую рабочую папку (так бывает вне Windows).

Путь вычисляется **один раз, при импорте `src.variables`**: переменную нужно задать до импорта `src`. Автотесты всегда задают `SCHEDULE_DATA_DIR` (`tests/__init__.py`, затем `requireIsolation()` проверяет изоляцию), чтобы не трогать настоящие данные пользователя. Папка `projects/` создаётся при импорте `src.variables`, папка `logs/` — при запуске сервера (`journal.setupLogging` вызывается при импорте `src.web.core`), `logs/builds/` — при первой сборке.

```
%APPDATA%\Schedule-Maker-1\
├── projects\
│   └── <имя проекта>\          ← по папке на проект, имя папки = имя проекта
└── logs\
    ├── app.log, app.log.1 … app.log.5
    └── builds\<ГГГГ-ММ-ДД ЧЧ-ММ-СС> <проект> <этап>.log
```

Имя проекта проверяет `projects.checkProjectName`, по порядку, и у каждого отказа свой текст: пустое имя (`web.error.project_name_empty`); символы `\ / : * ? " < > |` (`FORBIDDEN_NAME_CHARS`), точка в начале или в конце (`project_name_chars`); пробел (`project_name_spaces`); длина больше 80 знаков (`project_name_too_long`); управляющие (невидимые) символы, например табуляция из вставленного текста (`project_name_control`); зарезервированные имена Windows CON, PRN, AUX, NUL, COM1…9, LPT1…9, в том числе с расширением (`project_name_reserved`). Занятое имя — `project_name_exists`. Папки, имя которых начинается с точки, в список проектов не попадают. `project.projectPath` дополнительно проверяет, что путь лежит прямо внутри `projects/`.

### 1.2. Журналы (`logs/`, модуль `journal.py`)

- **`app.log`** — общий журнал (`setupLogging`): запуск, каждое действие (проект, имя, аргументы, итог) и ошибки. Файл до 2 МБ, хранится 5 старых частей.
- **`builds/*.log`** — по файлу на сборку (`openBuildLog`): параметры сборки и весь вывод решателя. Хранятся последние 50 (`KEEP_BUILDS`).

Журналы ничего не хранят для работы программы, их можно удалять.

### 1.3. Папка проекта

```
projects\<имя>\
├── settings.json                 всё, что ввёл человек (раздел 3)
├── answer.json                   принятое расписание (раздел 4); у нового проекта файла НЕТ
├── weights.json                  веса встроенных правил (раздел 5)
├── stages\                       построенные варианты
│   └── <этап>.variants\          например 1.variants, 2.variants, extra.variants
│       ├── 1.json, 2.json, …     варианты: формат как у answer.json
│       ├── accepted.json         {"number": N}: последний принятый вариант
│       ├── rejected.json         {"numbers": [N, …]}: отклонённые, по возрастанию
│       └── started.json          {"courses": [курс, …], "lessons": {курс: [[день, урок, предмет, [преподаватели]], …]}}: курсы этапа, которые уже шли при сборке, и их уроки на начало сборки (раздел 4)
├── versions\                     сохранённые версии (раздел 8)
│   └── <id>\                     id = ГГГГММДД-ччммсс или ГГГГММДД-ччммсс-2, -3…
│       ├── settings.json, weights.json, answer.json   копии (каких-то может не быть)
│       └── meta.json
├── settings.json.broken-<ГГГГММДД-ччммсс>     отложенный испорченный файл
├── weights.json.broken-<…> / answer.json.broken-<…>
└── answer.json.repaired          метка «расписание пришлось сбросить»
```

**Кто пишет и читает файлы:**

| файл | функции | замечания |
|---|---|---|
| `settings.json`, `weights.json`, `answer.json` | `project.load*/save*`, `tree.prepareProject` | Запись всегда целиком. Обычная запись атомарна: `files.writeJson` пишет `<файл>.tmp` и подменяет им файл через `os.replace`, до 10 попыток. После сбоя может остаться `*.tmp`; программа его не читает. Исключения — простое копирование (`shutil.copy`/`copy2`): `weights.json` нового проекта копируется из шаблона (`tree.repairWeights`), файлы версии копируются в проект при восстановлении (`versions.restoreVersion`). Новый проект создаётся **без `answer.json`**: «нет файла» читается как пустое расписание `{}`. |
| варианты | `variants.saveVariant` / `loadVariants` | Файл варианта пишется компактно, одной строкой (`indent=None`). Читаются только файлы `<число>.json`; нечитаемые молча пропускаются. Пишет их только сборка (`build._storeVariant`) и переписывание вариантов (`project.rewriteVariants`). |
| метки вариантов | `variants.markAccepted` / `acceptedNumber`, `setRejected` / `rejectedNumbers` | |
| версии | `versions.saveVersion` / `listVersions` / `restoreVersion` / `deleteVersion` | |

**Когда варианты этапа удаляются** (`variants.clearVariants` стирает всю папку этапа вместе с метками):
- новая сборка этапа — в момент, когда сохранён первый новый вариант (`build._storeVariant`). Остановленная до этого сборка оставляет прежние варианты;
- правка сетки, при которой сдвинулся хоть один столбец (`tabs/settings.setGrid`), — у всех этапов;
- добавление потока (`newStream`) — для его номера; удаление потока (`deleteStream`);
- отметка «Присоединяется к» у линейки (`setJoint`, раздел 3.12) — у этапа этого потока;
- удаление последних курсов раздела (`deleteLine`, `deleteCourse`): этап исчез, и `purgeCourses` стирает его папку (`variants.clearStaleVariants`);
- восстановление версии (`versions.restoreVersion`) — удаляется вся папка `stages/`.

Когда удалена последняя линейка или последний курс раздела, этап исчезает (раздел 3.8) вместе с папкой `stages/<этап>.variants/`: иначе старые варианты с удалёнными курсами снова показались бы, когда в раздел добавят курсы. Отметки времени преподавателей для этого этапа остаются; для номера нового потока их стирает `newStream` (раздел 3.4).

Варианты не попадают в версии. Они попадают в ZIP-архив проекта: архив пакует всю папку.

**Испорченные файлы** (`tree.prepareProject`, `setAside`):
- **`settings.json`** не читается или не объект → копия `settings.json.broken-<время>`, проект **не открывается** (`web.error.broken_settings`: «копия сохранена рядом»). Файл никогда не подменяется пустым проектом. Если файл испортился у **уже открытого** проекта, любое действие отвечает `web.error.settings_broken_open` («закройте проект и откройте снова», `project.loadSettings`): копию здесь никто не делает, её отложит `prepareProject` при следующем открытии.
- **`weights.json`** испорчен → копия, файл пишется заново из шаблона `src/files/weights.json`.
- **`answer.json`** испорчен → копия, записывается пустое расписание `{}` и создаётся пустой файл-метка `answer.json.repaired`. `projects.takeRepairedMark` при открытии удаляет метку и добавляет в ответ `message` (`web.answer_repaired`).
- **Во время работы** (не при открытии) испорченный `answer.json` даёт `ValueError("web.error.broken_answer")` (`files.readAnswer`). Человек видит текст, а не пустое расписание. Терпимое чтение (`project.loadAnswerOrEmpty`) есть только там, где расписание не меняется: ручная версия, версия перед восстановлением, выгрузка списка преподавателей.

## 2. Номер формата проекта

- **Поле:** `settings.json` → `"format"` (целое).
- **Текущее значение:** `tree.PROJECT_FORMAT = 1`.
- **Проверка:** `tree.isCurrentFormat(settings)`.

**Что программа делает с проектом другого формата:**

| где встречается | что происходит | текст для человека |
|---|---|---|
| открытие проекта (`prepareProject` → `projectSettings`) | `ValueError("web.error.old_project")`, файлы не меняются | `web.error.old_project` |
| импорт архива (`tree.importProjectArchive`) | ничего не распаковывается | `web.error.old_archive` |
| импорт: архив распакован, но `prepareProject` упал (`projects.importProject`) | папка нового проекта удаляется целиком | `web.error.not_project_archive` |
| восстановление версии (`tabs/save.restore`) | проверяется `settings.json` версии (нет или не читается — тоже «другой формат»), проект не меняется | `web.error.old_version` |
| список проектов (`projects.projectSummary`) | проект показывается всегда, формат не проверяется: его можно попытаться открыть или удалить | — |

Миграций нет. Программа понимает только один формат.

**Временное переходное правило** (`isCurrentFormat`, `numberFormat`, `UNNUMBERED_LEFTOVERS`). Проект **без поля `format`** считается текущим, если в нём `"pair_rules_version": 2` и `"base_math_version": 2`. Так помечены проекты, сохранённые программой 04.10.2026 до появления номера формата. При открытии такому проекту `numberFormat`:
- удаляет устаревшие ключи `UNNUMBERED_LEFTOVERS`: `joint_pairs_version`, `seminar_subjects_version`, `line_names_version`, `iterations_version`, `base_math_version`, `pair_rules_version`, `max_teachers_per_course`, `max_teachers_per_stream`, `display`, `online_start_time`, `lesson_duration_minutes`, `break_duration_minutes`, `extra_slots`;
- удаляет поле `parallel` у курсов;
- ставит `"format": 1`.

Когда у всех проектов, архивов и версий появится `format`, ветку, `numberFormat` и `UNNUMBERED_LEFTOVERS` нужно удалить. Важно: версии внутри проекта тоже могут быть без номера, `restore` проверяет их тем же правилом.

**Что ещё делает `prepareProject` при каждом открытии.** Она вызывается при создании, открытии, импорте и после восстановления версии:
1. Дописывает недостающие **ключи верхнего уровня** значениями `tree.newProjectSettings()` (`setdefault`). Внимание: у проекта без `classes` или `subjects` появится стандартная программа школы.
2. Дописывает в `weights.json` веса, которых в нём нет, из шаблона (`repairWeights`).
3. Пересчитывает `working_days_per_week` и `max_lesson_count_per_day` из `day_grid` (`grid.applyDayGrid`) и приводит отметки `together_with` к правилам (`joint.syncJointSettings`, раздел 3.12).
4. Записывает `settings.json`.
5. Если `answer.json` есть, переписывает его: курсы-копии получают уроки своих источников (`tree.syncAnswer` → `joint.syncJointAnswer`). Нового файла не создаёт. Так согласуются и файлы, записанные мимо `project.saveAnswer`: восстановленная версия, проект из `tools/create_school_project.py`, ручная правка.

## 3. `settings.json`

### 3.1. Ключи верхнего уровня

Колонка «Нов.» — есть ли ключ в новом проекте (`tree.newProjectSettings`). Слово «страница» значит, что страница получает данные через `state` в уже обработанном виде, а не сам ключ. Во «вход» движка (`solver_input.buildStageSettings`) попадает глубокая копия всех ключей, но движок читает только отмеченные.

| ключ | тип | смысл | кто пишет | кто читает | Нов. (значение по умолчанию) |
|---|---|---|---|---|---|
| `format` | int | номер формата (раздел 2) | `newProjectSettings`, `numberFormat` | `tree.isCurrentFormat` | да, `1` |
| `working_days_per_week` | int | номер последнего дня с уроками + 1 (`1`, если уроков нет совсем); **производное от `day_grid`** | `grid.applyDayGrid` (через `setDayGrid` и `prepareProject`) | `grid.missingSlots`, **движок** (`JOB_WEEK_LENGHT`) | да, `5` |

| `day_grid` | `[[str]]`, 7 списков | время уроков по дням пн…вс, раздел 3.9 | `tabs/settings.setGrid`, `copyMonday` | Python (`grid.dayGrid`); страница: `state.grid`; движок не читает | да, будни `DEFAULT_DAY`, сб и вс `[]` |

Остальные ключи программа не читает. Устаревшие ключи из `UNNUMBERED_LEFTOVERS` удаляет только `numberFormat`.

### 3.2. Курс: `classes.custom_groups[*]`

Курс («группа» в данных) — **один предмет одной линейки в одном разделе**.

```json
{
  "name": "Поток 1 — ЕГЭ основной — Русский язык",
  "program": "ЕГЭ основной",
  "line": "ЕГЭ",
  "subjects": ["Русский язык"],
  "stream_id": 1,
  "start_date": "2026-09-07",
  "end_date": ""
}
```

Курс без потока:

```json
{
  "name": "Семинар ЕГЭ продвинутый: Русский язык",
  "program": "Семинары",
  "line": "Семинар ЕГЭ продвинутый",
  "subjects": ["Русский язык"],
  "stream_id": null,
  "start_date": "2026-10-05",
  "end_date": "",
  "block": "extra"
}
```

| поле | смысл |
|---|---|
| `name` | **Ключ курса во всём проекте**: `classes.lessons`, `constants`, `teachers[*].subjects[*].classes / assigned`, `teachers[*].forbidden`, `answer.json`, варианты, `params.value` своих правил. Строится **только** функцией `courses.courseName(section, line, subject)` из `nameParts`. Разбирать имя нельзя: подпись берётся из `courses.courseLabel`. |
| `program` | Программа. В потоке — сама линейка («ОГЭ», «ЕГЭ основной»…). У доп. курсов — `"Семинары"` (`EXTRA_PROGRAM`): на неё завязано правило `non_overlapping_programs`. У блоков `may` и `summer` — название блока («Майские марафоны», «Летняя школа»). См. `courses.sectionProgram`. |
| `line` | Линейка для правил пар. В потоке это `courses.courseLine(program)`: оба уровня ЕГЭ дают `"ЕГЭ"`, остальное — сама программа. У блока — линейка как есть («Семинар ОГЭ»). Движок без `line` берёт `program`. |
| `subjects` | Список из **одного** предмета (`model.courseSubject` берёт первый). |
| `stream_id` | Номер потока (int) или `null` у курсов без потока. Движок: не int → поток −1. |
| `block` | Только у курсов без потока: `"extra"`, `"may"`, `"summer"` (`courses.BLOCKS`). Нет поля → `"extra"` (`model.sectionOf`). |
| `start_date` | Начало курса, `"ГГГГ-ММ-ДД"`. От него зависит «курс уже идёт» (`courses.courseStarted`). Пусто → «с начала времён», и курс никогда не считается идущим. |
| `end_date` | Конец курса. `""` → до `calendar_end_date` (`model.courseDates`). |
| `together_with` | Необязательное, только у курса-копии: номер (int) более раннего потока, вместе с которым идёт линейка курса. Нет поля → курс обычный. Подробно — раздел 3.12. |

Даты сравниваются **как строки**, поэтому формат `ГГГГ-ММ-ДД` обязателен.

**Курс считается** (определения живут в `courses.py`):
- **«уже идёт»** (`courseStarted`): дата старта наступила и у курса есть уроки в `answer.json`;
- **«зафиксирован»** (`courseLocked`): идёт и все его уроки расставлены.

Для курса-источника и его копий (раздел 3.12) есть обёртки `sharedStarted` и `sharedLocked`: проверка верна, если она верна хотя бы для одного курса группы «источник + копии». Ими пользуются `setHours`, `setTeacher`, `setPins` и `solver_input.pinPlan`: если копия уже идёт, источник менять нельзя. `stages.startedCourses` считает источник идущим по тому же правилу.

### 3.3. Нагрузка: `classes.lessons`

```json
{"Поток 1 — ОГЭ — Литература": {"Литература": 1}}
```

`{курс: {предмет: уроков в неделю}}`. Пишут `courses.addCourse`, `copyLineToStreams` и `tabs/classes.setHours` (от 1 до числа дней с уроками). У курса-копии запись всегда равна записи источника: её выравнивают `joint.setJointLine` и `syncJointSettings` при каждой записи `settings.json` (раздел 3.12). Python пустое значение считает нулём (`courses.courseLoad`), а **движок требует целое число** (`count.get<int>()`). Курс без записи — 0 уроков.

### 3.4. Преподаватель: `teachers[имя]`

```json
"Иванова А. А.": {
  "subjects": [
    {"subject": "Математика",
     "classes":  ["Поток 1 — ОГЭ — Математика", "…"],
     "assigned": ["Поток 1 — ОГЭ — Математика"]}
  ],
  "forbidden": ["Поток 2 — ОГЭ — Математика"],
  "availability": {
    "1":     {"free": [[0, 2], [4, 1]], "possible": [[1, 0]]},
    "extra": {"free": [], "possible": []}
  }
}
```

**`subjects[*]`** — предметы преподавателя:
- `classes` — «может вести»: из них выбирает решатель, до подбора и во время него (смена преподавателя, раздел 6.4). Принятие варианта со сменой преподавателя `classes` и `assigned` не меняет (раздел 4);
- `assigned` — «ведёт»: закреплён, решатель такому курсу преподавателя не меняет. Курс из `assigned` всегда есть и в `classes`. Движок учитывает `assigned`, только если курс есть в `classes`;
- `assigned` может отсутствовать: новый предмет записывается как `{"subject", "classes"}` без `assigned` (`courses.setTeacherSubjects`). Новый преподаватель (`newTeacher`) — `{"subjects": [...], "availability": {}}`, без `forbidden`.

Новый предмет начинается со всех курсов, где у предмета ненулевая нагрузка, кроме запрещённых (`courses.setTeacherSubjects`). Новый курс попадает в `classes` всем преподавателям предмета, кроме тех, кому он запрещён (`courses.offerCourse`).

**Отношение «преподаватель — курс»** (`courses.COURSE_STATES`, `teacherCourseState`): `"no"` → `"may"` (в `classes`) → `"assigned"` (в `classes` и `assigned`) → `"forbidden"` (в `forbidden`).

**Правило «курс ведёт только один преподаватель»** описано в одном месте — `courses.assignTeacher`. Закрепление одного преподавателя снимает `assigned` у остальных, но `classes` у них остаётся.

Курс-копию (раздел 3.12) не «ведёт» никто: `joint.setJointLine` и `syncJointSettings` снимают её из `assigned` тем же `assignTeacher(…, None)`. Преподаватель копии — тот, кто стоит на уроках источника.

**`forbidden`** — «вести нельзя». Хранится на уровне преподавателя, а не предмета, поэтому переживает удаление и повторное добавление предмета. Пустой список удаляется (`setTeacherCourseState`); поля может не быть.

**`availability[этап]`** — отметки времени на этапе, по ключу этапа (раздел 3.11). Слот — `[день, урок]`, считая с 0, понедельник = 0.
- `"free"` — **«НЕ МОЖЕТ»**. Имя историческое и обманчивое, так ключ называет движок. Смысл описан один раз — в `model.teacherAvailability`.
- `"possible"` — «может, но лучше не надо» (мягкий штраф `teacherPossibleSlot`).
- Все остальные слоты — «удобно».

Отметки этапа создаются пустыми при первом обращении (`model.teacherAvailability`). Читать их без изменения данных — `model.stageMarks`, `cannotSlots`, `possibleSlots`. Пишут `cycleAvailability` (по кругу: удобно → может → не может → удобно), `copyAvailability` и `grid.remapSettings`. Отметки `availability[str(поток)]` у всех преподавателей стирает `courses.clearStageMarks`: при удалении потока (`removeStream`) и при добавлении нового (`newStream`), потому что номер нового потока мог остаться от потока, который пропал без удаления (удалили все его линейки), и новый поток иначе получил бы чужие «не может».

### 3.5. Закрепления: `constants`

```json
{"Поток 1 — ОГЭ — Математика": {"0-1": "Математика", "3-0": "Математика"}}
```

`{курс: {"день-урок": предмет}}`. Ключ слота разбирает `grid.pinSlot`. У курса-копии (раздел 3.12) закреплений нет: их убирают `joint.setJointLine` и `syncJointSettings`, а время копии задают закрепления источника. Курс без закреплений удаляется из `constants` в `courses.setPinnedSlots`; но `grid.remapSettings` (правка сетки) может оставить у курса пустой словарь `{}`, поэтому читатели должны принимать и его. Движок пропускает значения не-строки, `""` и `"-"`.

`setPins` сначала приводит слоты из формы к парам целых (`tabs/classes.pinsFromForm`: строки из цифр тоже принимаются, всё остальное — ошибка `web.error.no_slot`), затем проверяет закрепления (`checkPins`): слот есть в сетке, не больше одного урока в день, закреплений не больше, чем уроков у курса. У идущего курса закрепления менять нельзя.

Во входе движка к `constants` добавляются уроки идущих курсов и курсов из режима keep (`solver_input.pinStartedCourses`; что именно закрепляется, решает `pinPlan`, раздел 6.2). Закрепление само по себе задаёт только время, преподавателя выбирает решатель; у идущих курсов и курсов из keep преподаватель фиксируется отдельно — через `assigned` во входе (раздел 6.2).

### 3.6. Пары

- **`joint_subject_pairs`** и **`soft_subject_pairs`** — списки неупорядоченных пар предметов `[a, b]`. Состояние пары (`pairs.PAIR_ALLOWED` / `PAIR_SOFT` / `PAIR_HARD` = `"allowed"` / `"soft"` / `"hard"`; соответствие ключам — `PAIR_KEYS`) читает `pairs.subjectPairState`, а меняет `setSubjectPairState`. Пара, которой нет ни в одном списке, — «можно». Пара не может быть в обоих списках сразу. Пары действуют только **внутри одной линейки одного потока** (`pairs.sameLine`).
- **`non_overlapping_programs`** — пары программ, действуют в обе стороны (`pairs.programPairs`).

Производные правила не хранятся, а вычисляются:
- пары уровней ЕГЭ — `pairs.isLevelPair`;
- «сдают вместе» — `togetherPairs`, то есть soft + hard;
- «в разные дни» — `sameDayMatters`, кроме `COMMON_SUBJECTS` = «Русский язык», «Математика», «Математика база».

### 3.7. Свои правила: `custom_penalties[*]`

```json
{"id": "1a2b3c4d", "name": "Без химии в пятницу вечером", "template": "time", "weight": 300,
 "params": {"target": "subject", "value": "Химия", "days": [4], "times": ["19:40 - 21:10"]}}
```

`id` — 8 hex-символов (`penalties.newPenalty`), `weight` — int (0 — правило выключено для решателя, но нарушения всё равно считаются). Шаблоны — `penalties.RULES`, допустимые цели — `penalties.TARGETS`:

| `template` | `params` | что считается нарушением |
|---|---|---|
| `time` | `target` ∈ all, line, subject, course, teacher; `value`: str (обязателен для line, subject, course; у teacher `""` = каждый преподаватель); `days`: [int 0..6], непустой; `times`: ["ЧЧ:ММ - ЧЧ:ММ"], непустой | урок цели в выбранном дне и времени. Время сравнивается **текстом** с `day_grid` (`penalties.penaltySlots`). При правке сетки время переименовывается (`renamePenaltyTimes`). |
| `daily_limit` | `target` ∈ teacher, line; `value` (`""` = каждый); `limit`: int ≥ 0 | каждый урок сверх лимита в день: у преподавателя или у всех курсов линейки одного раздела вместе |
| `adjacent` | `target` ∈ all, line, subject, course; `value` (обязателен, кроме all) | каждая пара соседних дней (d и d+1), в которые у курса цели есть уроки |
| `same_day` | `first`, `second`: разные предметы; `target` нет | каждый общий день у пары курсов с этими предметами в одной линейке одного раздела |

«Линейка» в `line` и `same_day` — `courses.lineOf` и раздел курса (`penalties.lineGroups`): в потоке это программа, поэтому «ЕГЭ основной» и «ЕГЭ продвинутый» здесь — **разные** линейки (в отличие от пар предметов, где оба уровня — одна линейка `"ЕГЭ"`); блоки тоже участвуют.

Проверка при сохранении — `tabs/run.checkPenalty` / `checkPenaltyParams`. Правила, нацеленные на удалённый курс или преподавателя, удаляются (`penalties.dropTargeted`). Цель `line` — линейка как её показывает `courses.lineOf`.

Число нарушений своего правила в ответе `/variants` лежит в `metrics.custom[<id>]` (раздел 7.6); страница берёт его оттуда по `id` правила. Ключ `"custom:<id>"` (`penalties.CUSTOM_PREFIX`; собирает только `customKey`, разбирает только `customId`) — внутренний ключ строки своего правила в книге Excel с вариантами (`tabs/export.variantsBook` → `export.compareSheet`); в API и в файлах проекта его нет.

### 3.8. Названия курсов и этапов

**Раздел** (section) — где курс стоит на вкладке «Курсы»: номер потока (**int**) или ключ блока (**str**). `None` как аргумент `section` функций `courses` и `model` — то же, что `"extra"` (`model.normalizeSection`). В данных раздела `None` нет: раздел курса вычисляет `model.sectionOf` (нет `stream_id` и `block` → `"extra"`). Сервер `None` как раздел не принимает (`project.requireSection`).

**Этап** (stage) — курсы одного раздела, которые строятся одним запуском решателя. Ключ этапа — раздел **строкой** (`model.stageKey`):

| ключ этапа | что это | название (`stages.stageLabel`) |
|---|---|---|
| `"1"`, `"2"`, … | поток N: курсы с `stream_id = N` | «Поток N» (`stage.stream` + номер) |
| `"extra"` | доп. курсы, семинары: `block` = `"extra"` или нет `block` | `stage.extra` = «Доп. курсы» |
| `"may"` | майские марафоны | `stage.may` = «Майские марафоны» |
| `"summer"` | летняя школа | `stage.summer` = «Летняя школа» |

Этап существует, пока в нём есть хотя бы один курс (`stages.stageExists`). Поток без курсов программа не хранит. `stages.getStages` сортирует этапы по самой ранней `start_date` их курсов; этапы без дат идут в конце.

**Названия курсов** (`courses.courseName`):

| раздел | название | пример |
|---|---|---|
| поток | `«Поток N — <линейка> — <предмет>»` | «Поток 2 — ЕГЭ основной — Математика» |
| `extra` | `«<линейка>: <предмет>»` | «Семинар ОГЭ: Математика» |
| `may` / `summer` | `«<название блока> — <линейка> — <предмет>»` | «Летняя школа — ЕГЭ основной — Математика» |

Разделитель — длинное тире с пробелами `" — "`.

Ключ этапа используется:
- в `teachers[*].availability`;
- в имени папки вариантов `stages/<этап>.variants`;
- в аргументах `stage` действий и адресов;
- в `meta.json["stages"]`.

### 3.9. Сетка: `day_grid`

7 списков (пн…вс), в каждом до 6 строк времени (`grid.MAX_LESSONS_PER_DAY`) в нормальной форме `"ЧЧ:ММ - ЧЧ:ММ"` (`grid.parseTime`). Пустой день — выходной. В файле пустых ячеек нет (`grid.setDayGrid` → `compactGrid`): уроки дня идут подряд, номер урока — индекс в списке.

Решатель работает с прямоугольной неделей `working_days_per_week × max_lesson_count_per_day`. Слоты, которых нет в сетке, он получает как занятые (`grid.missingSlots` → `free` преподавателей и `blocked_slots` курсов).

При сдвиге столбцов `setGrid` переносит `constants`, `availability` и `answer.json` на новые номера уроков (`grid.columnMapping`, `remapSettings`, `remapAnswer`).

### 3.10. Даты блоков

`block_dates` = `{"may": {"start": "ГГГГ-ММ-ДД", "end": "…"}, "summer": {…}, "extra": {…}}`. Дата раздела хранится **в его курсах** (`start_date` / `end_date`; `setDates` → `courses.setSectionDate`). У блока она дополнительно запоминается в `block_dates`, чтобы блок без курсов помнил свои даты (`courses.saveBlockDate`).

Блок без сохранённых дат получает сезон по умолчанию: `courses.BLOCK_DATES`, май 1–31 и лето 1.06–31.08 в году `calendar_end_date`, или в текущем году, если его нет (`courses.blockDates`). У `extra` дат по умолчанию нет.

### 3.11. Сводка: кто какие отметки пишет по этапам

| что | ключ этапа |
|---|---|
| `teachers[*].availability[<этап>]` | `"1"`, `"extra"`… |
| `stages/<этап>.variants/` | то же |
| `meta.json → stages` | этапы, у которых в расписании есть хотя бы один урок (`stages.acceptedStages`; уроки копий не в счёт, как в `stages.countedCourses`) |

### 3.12. Линейка присоединяется к более раннему потоку: `together_with`

Ученики двух потоков могут ходить на одни и те же уроки линейки, например «ЕГЭ основной» Потоков 1 и 2. Тогда у линейки более позднего потока стоит отметка «Присоединяется к: Поток N» (у Потока N — пометка «К этой линейке присоединяется Поток M»), и эти уроки программа считает одним курсом. В коде и в этом файле то же самое называется «вместе с» (`together_with`, `joint*`). Код — модуль `src/modules/functions/joint.py`, слой 3.

```json
{"name": "Поток 2 — ЕГЭ основной — Математика", "program": "ЕГЭ основной", "line": "ЕГЭ",
 "subjects": ["Математика"], "stream_id": 2, "start_date": "2026-11-23", "end_date": "",
 "together_with": 1}
```

**Слова:**
- **курс-копия** — курс линейки потока-копии с полем `together_with = N`. Поле ставится только тем курсам, у которых в той же линейке Потока N есть курс того же предмета;
- **курс-источник** — этот курс Потока N. Его имя строится через `courses.courseName(N, линейка, предмет)`, имя копии не разбирается;
- **линейка идёт вместе с Потоком N**, если хотя бы у одного её курса действующая отметка N (`joint.lineJoint`). Разных N в одной линейке не бывает. Курсы линейки, предмета которых нет в Потоке N, остаются обычными.

**Правила:**
- N меньше номера своего потока. У блоков отметки нет.
- Цепочек нет, источник всегда корневой. Поток, линейка которого сама идёт вместе с кем-то, выбрать нельзя. Линейка, с которой уже идёт другой поток, сама копией стать не может.
- У копии `classes.lessons` равно записи источника, закреплений (`constants`) нет, в `assigned` её нет ни у кого.
- В `answer.json` у копии те же уроки, что у источника (раздел 4).
- Поле читается мягко. Если источника нет (курс, линейку или поток удалили) или отметка недействительна (свой или более поздний поток, источник сам копия), `joint.jointSource` возвращает `None`. При записи `syncJointSettings` такое поле убирает, а уроки бывшей копии остаются.

**Кто пишет:**
- `joint.setJointLine(settings, section, line, source, answer, today=None)` — единственная функция, которая ставит и снимает отметку у всей линейки (действие `setJoint`, раздел 7.4). Отказ — `ValueError(причина, номер потока)`: `"invalid"`, `"chain"`, `"has_copies"`, `"started"`. Возвращает курсы, уроки которых в `answer` пропадут или сменятся. При снятии сама убирает уроки бывших копий из `answer`. При смене источника (линейка была с Потоком 1, выбрали Поток 2) бывшие копии, предмета которых в новом источнике нет, становятся обычными курсами и тоже теряют уроки; они входят в возвращаемый список, поэтому сервер сохраняет версию, а если такой курс уже идёт — отказ `"started"`. Обычные курсы линейки, которые копиями не были, своих уроков не теряют.
- `courses.addCourse` — новый курс в отмеченной линейке («Добавить предмет», «Скопировать в другие потоки») сразу получает `together_with` и часы источника, если такой предмет есть в Потоке N. Новый поток (`newStream`) отметку не наследует.
- `joint.syncJointSettings(settings)` — убирает недействительные поля, выравнивает часы, снимает закрепления и «ведёт» у копий. Вызывают `project.saveSettings` перед каждой записью и `tree.prepareProject` при открытии.
- `joint.syncJointAnswer(settings, answer)` — `answer[копия] = deepcopy(answer[источник])`, а если у источника нет уроков, ключа копии нет. Вызывают `project.saveAnswer(project, answer, settings=None)` (без `settings` они читаются с диска, поэтому действие, которое меняет и настройки, пишет их первым) и `tree.prepareProject`. Так копии сами следуют за принятием варианта, закреплениями и преподавателем источника, «Убрать из расписания» и снятием преподавателя.
- `joint.followSources(settings, sources, target, copies=None)` — то же правило для другого расписания: копиям `copies` в `target` уроки источников из `sources`. Так вариант потока-копии на «Предпросмотре» показывает и оценивает копии с нынешними уроками источников (`ranking.rankedVariants`).

Для согласованного проекта обе синхронизации ничего не меняют.

**Кто читает.** Чтение — `jointSource`, `jointCopies` (`{копия: источник}`, только живые), `jointRoot` (источник или сам курс), `jointGroup` (`[источник, копии…]`), `lineJoint`, `jointOptions`; помехи новых часов копий соседям — `joint.copyConflicts` (вопросы `setJoint` и `accept`): соседи — курсы любого этапа, которые идут в даты копии (её поток, блоки, более поздние потоки), кроме курсов, уроки которых задаёт этап источника (сам источник, его поток и их копии: это помехи самого источника); с `same_stage=True` — только курсы этапа копии (вопрос `web.preview.confirm_joint_stale`). Этапы, где стоят мешающие уроки, — `project.conflictStages` (`{stages}` в текстах вопросов: их варианты и составлять заново; если мешающий урок — урок копии другой линейки, называется этап её источника (`courses.copyRoot`): уроки копии ставит не её поток, а поток-источник); общие уроки во время, где у преподавателя на этапе потока-копии «не может», — `joint.copyCannot(settings, answer, copies, before=None)` → `[(преподаватель, день, урок, копия)]` (с `before` — только новые для преподавателя места). Это не запрет, а предупреждение: движок соблюдает отметки этапа источника, а время копии задаёт источник. Его показывают вопросы `setJoint` и `accept` и поле `jointCannot` состояния (раздел 7.5). `courses.py` лежит ниже слоя `joint` и читает отметку своими `copySource`, `copySources`, `sharedCourses`, `lineTogetherWith` по тому же правилу; от уже прочитанных `{копия: источник}` — `copyRoot`, `copiesOf` (копии данных курсов), `copyFollowers` (`{источник: [копии]}`). Пара «источник + копия» нигде не считается дважды:
- накладки (`stages.teacherClashes`, `teacher_card`, `courses.teacherConflicts`, `peerSlotConflicts`) — общий урок не накладка, урок третьего курса в эти часы — накладка;
- лимит курсов преподавателя — один курс (`teacherConflicts`, `occupiedByOtherStages`, выгрузка «Список преподавателей»);
- «нужен ещё преподаватель» (`staffing`) и метрики вариантов (`missing`, `teacherClash`, `teacherPossibleSlot`, рабочие дни и «окна» преподавателя) — без копий. Уровни ЕГЭ, пары «нежелательно» и «в один день» считаются с копиями.

Сборка этапа копии не меняет (`stages.changeableCourses` без копий), во вход движка они не попадают (раздел 6.2).

Номер формата не меняется (раздел 9.1). Прежняя версия программы поле не заметит: покажет накладки и станет подбирать копии как обычные курсы, но данные не испортит.

## 4. `answer.json` и файлы вариантов

```json
{
  "Поток 1 — ОГЭ — Математика": [
    [ {"subject": "#", "teachers": []}, {"subject": "Математика", "teachers": ["Иванова А. А."]}, {"subject": "#", "teachers": []} ],
    [ … ], …
  ]
}
```

- **Верхний уровень** — `{курс: неделя}`. Курса может не быть: у него ещё нет уроков в расписании. Курс может быть и с пустой неделей (все ячейки `"#"`): так пишет ответ решателя (раздел 6.4), и такой курс тоже «без уроков». Поэтому там, где пустая неделя меняет ответ (вопрос об удалении, версия «Перед: …», число уроков), «курс есть в расписании» проверяется через `model.hasLessons` (есть хотя бы один урок). В остальных местах (список keep при сборке, `variants.isAccepted`, проверка «расписание пусто» при выгрузке) достаточно наличия ключа: пустая неделя там ничего не меняет.
- **Неделя** — список дней, индекс 0 = понедельник. **День** — список ячеек, индекс = номер урока в дне (с 0, по `day_grid`).
- **Ячейка** — `{"subject": предмет, "teachers": [имя]}`. Преподаватель всегда один или ни одного: пустой список значит «урок без преподавателя».
- **Пустая ячейка** — `{"subject": "#", "teachers": []}` (`model.EMPTY_SUBJECT`, `model.emptyCell`).
- **Урок** (`model.isLesson`) — ячейка, где `subject != "#"`. Ячейка без поля `subject` тоже считается пустой.

**Длина недели и дней не фиксирована.** Проверено на копии проекта:
- `answer.json` после импорта или правки сетки «рваный», по сетке: 7 дней с длинами 3, 3, 3, 3, 3, 6, 2;
- ответ решателя и варианты прямоугольные: `working_days_per_week` дней × `max_lesson_count_per_day` уроков, например 7 × 6;
- после принятия варианта в одном `answer.json` встречаются недели обоих видов.

Читатели обязаны проверять границы, как это делают `model.lessonEntries`, `courses.ownSlotConflicts` и `courses.moveLessons`. В слотах, которых нет в сетке, уроков не бывает.

**Курсы-копии** (раздел 3.12). Уроки копии хранятся как настоящие: `answer[копия]` — глубокая копия `answer[источник]` (те же дни, уроки, предмет и преподаватель). Если у источника нет уроков (`model.hasLessons`), ключа копии нет: копия «ждёт Поток N». Поэтому календарь со своими датами копии, `stageTotals`, «Расписание», версии и стартовый экран работают с копией как с любым курсом. Согласует уроки `joint.syncJointAnswer` при каждой записи `answer.json` через `project.saveAnswer` и при открытии проекта. Исключение — удалённый источник: бывшая копия становится обычным курсом и сохраняет свои уроки.

**Файл варианта** `stages/<этап>.variants/<N>.json` имеет тот же формат, но содержит **только курсы этапа** (`build._storeVariant`):
- уроки курсов этапа из ответа решателя;
- поверх них — зафиксированные курсы и курсы-копии этапа с уроками ровно как в `answer.json` на начало сборки (`build._fixedCourses`; решатель копии не получает, копия, которая ждёт источник, в вариант не попадает);
- идущие курсы, которых нет в ответе решателя (например, без преподавателя).

Номера вариантов одной сборки идут подряд с 1. Вариант, который совпал с уже сохранённым вариантом этой же сборки (то же содержимое файла), не сохраняется (`build._storeVariant`); варианты прошлой сборки не в счёт — их заменяет первый новый.

**Принятие варианта:** `stages.mergeStageAnswer` заменяет в `answer.json` курсы этапа, кроме зафиксированных и копий (`stages.changeableCourses`), курсами варианта. Перед этим `variants.dropUnknownTeachers` убирает из варианта удалённых преподавателей. Курсы этапа, которых нет в варианте, из расписания пропадают. Копии курсов этого этапа в более поздних потоках получают новые уроки своих источников (`syncJointAnswer`).

**Вариант, собранный до начала курсов.** У начавшегося курса время и преподаватель не меняются (правило заказчика). Курс, который идёт, но ещё не все его уроки на месте, не зафиксирован и принимается из варианта (так он получает недостающие уроки). Свежая сборка у такого курса ничего не меняет (закрепляет все его уроки и преподавателя), но вариант могли собрать, пока курс ещё не шёл. `stages.staleStarted(settings, answer, stage, variant)` → `[курс]` (в порядке проекта): идущие курсы этапа (`courses.sharedStarted`, без копий), у которых хотя бы один урок из `answer.json` в варианте стоит не там или с другим предметом, либо на каком-то уроке варианта нет преподавателя или есть преподаватель, которого на уроках курса в расписании не было. Преподаватели, которых уже нет в проекте, не сравниваются; если в расписании у курса не осталось ни одного преподавателя из проекта, сверяется только время. Курсы, которые шли уже при сборке, здесь не проверяются (параметр `built`): сборка пишет их в `started.json` папки вариантов вместе с первым вариантом (`variants.saveBuildStarted(path, stage, courses, answer)`: с расписанием на начало сборки — и их уроки, `"lessons"`, `variants.startedLessons`; читает `variants.buildStarted(path, stage, answer)`; нет файла или он испорчен — `None`, проверяются все идущие курсы). С нынешним `answer` курс, чьи уроки с начала сборки поменялись (приняли другой вариант этапа, вернули версию), в `built` не попадает: вариант собран по прежнему расписанию, и он проверяется здесь (текст отказа говорит и об этом: «…или их уроки в расписании были другими»). Без `"lessons"` (метка старой программы) сверки нет. Непустой список — `accept` отказывает (`web.error.variant_stale_started`, `{courses}`), и `force` этот отказ **не снимает**: этап надо составить заново. На «Предпросмотре» такой вариант виден по полю `staleStarted` (раздел 7.6): он стоит после остальных, не бывает «лучшим», страница не выбирает его сама, в шапке его столбца и на его вкладке над неделей — пометка `web.export_variants.stale` («нельзя принять», та же, что в Excel), под таблицей — `web.preview.cannot_accept` с причиной `web.preview.stale_started` (`{courses}` — короткие подписи курсов через «;»; при обеих причинах сразу они идут через «;» в одной фразе `cannot_accept`; пометки «если принять…» — `web.preview.moved`, `web.preview.joint_moves`, `web.preview.teacher_changes` — у него не пишутся), и «Принять» не нажать.

**Вариант сдвинул урок курса, который шёл уже при сборке** (решение заказчика 06.10.2026). Сборка закрепляет уроки и преподавателя таких курсов, но решатель не ставит закрепление, если прежнее место стало невозможным (преподаватель отметил «не может», в это время у него урок другого этапа или закреплён урок курса другого этапа, изменилась сетка, у преподавателя больше нет предмета курса). Такой вариант тоже не принимается: время идущего курса не меняется. `stages.movedStarted(settings, answer, stage, variant, built)` → `[(курс, [(день, урок, причина, подробность)])]` — курсы из `built` с тем же сравнением, что у `staleStarted` (`stages.startedChanges`); причина для каждого сдвинутого урока — `stages.pinConflicts(context, курс, предмет, места, преподаватель)` для его прежнего места в `answer.json`, так, как помехи видит решатель (`stages.pinContext` этапа: закрепления он ставит по курсам в порядке их имён, уроки других этапов занимают преподавателя, если пересекаются по датам со всем этапом): как у `courses.slotConflicts` — `missing`, `unavailable`, `busy` (урок другого этапа, копии этапа или идущего курса этапа, чьё имя по алфавиту раньше), `pair` и `program` (с такими же уроками и закреплениями), — и `elsewhere`: у преподавателя урока в это время закреплён вручную урок курса, которого в это время нет в расписании, — другого этапа (`stages.pinnedForTeacher`; решатель считает это время занятым) или курса этого этапа, который ещё не начался и чьё имя раньше; `noteacher` / `lostsubject` — у преподавателя из расписания больше нет предмета курса (`stages.teacherLeft`): «может вести» никто, курс некому вести (`courses.nobodyTeaches`) / курс поведёт другой преподаватель; одна строка на курс (подробность — этот преподаватель) на первом уроке курса в `answer.json`, как у `blockedStarted`; `unplaced` — помеху найти не удалось (возможно, её уже убрали); `teacher` — время то же, но урок ведёт другой преподаватель (подробность — прежний, место — первый такой урок). `built` пустой или `None` — пустой список; `context` — уже собранный `pinContext` (иначе собирается, если понадобится). `project.movedStartedItems` превращает его в `[{"course", "lines"}]` (строки «день и час: причина», `project.conflictLines`, тексты `menu.main.tab.classes.slot_<причина>`). Непустой — `accept` отказывает (`web.error.variant_moved_started`, `{lessons}` — на каждый курс строка «• курс», под ней строки «день и час: причина» с отступом), `force` не снимает; на «Предпросмотре» — поле `movedStarted` (раздел 7.6), та же пометка «нельзя принять», под таблицей и в подсказке «Принять» — `web.preview.cannot_accept` с причиной `web.preview.moved_started` (`{lessons}` — «короткая подпись курса — день и час: причина» через «;»). Чтобы вариант снова можно было принять, завуч убирает причину (если она ещё есть) и составляет этап заново.

**Предупреждение до сборки.** `stages.blockedStarted(settings, answer, stage, context=None)` → `[(курс, [(день, урок, причина, подробность)])]`: идущие курсы этапа с преподавателем из проекта (`stages.startedPins` → `[(курс, предмет, места, преподаватель, зафиксирован)]`; зафиксированные сюда не попадают — их в варианты переносит сборка), и их уроки из `answer.json`, для которых `pinConflicts` нашёл помеху (или у преподавателя больше нет предмета — `noteacher` / `lostsubject`, одна строка); причины — как у `movedStarted`, без `unplaced` и `teacher`. Поле этапа `blockedStarted` (раздел 7.5) — «Запуск» пишет под статусом потока `web.run.started_blocked`; `pinForecast` такие уроки закреплёнными не считает (раздел 6.2). Состояние строит `stages.pinContext` один раз на этап и отдаёт его и `blockedStarted`, и обоим прогнозам. Контекст — свежей сборки и для прогноза с галочкой: ручное закрепление курса из `keep`, которое вход отбросит (`plannedPins`), он всё равно считает помехой курсам с именем позже — тогда прогноз с галочкой бывает меньше, чем закрепит решатель, а предупреждение — лишним (редкий случай: закрепление поставлено «всё равно» на время урока другого курса того же преподавателя). Во входе решателя ручных закреплений идущего курса и курса из `keep` не больше, чем часов сверх его уроков из расписания (`solver_input.plannedPins`: лишними первыми идут те, что решатель всё равно не поставит, затем последние по порядку мест; закрепление, которое решатель поставил бы на место урока идущего курса с именем позже и тем вытеснил бы этот урок, не остаётся никогда): решатель перебирает закрепления по порядку и лишние отвергает — иначе он мог бы отвергнуть урок из расписания, и каждый вариант сдвинул бы урок идущего курса.

**Смена преподавателя при принятии.** Вариант может отдать уже принятый курс другому преподавателю из «может вести» (ход 4 движка, раздел 6.4). Принятие пишет его в ячейки уроков `answer.json` (и в копии курса через `syncJointAnswer`), но **не в `settings.json`**: «ведёт» не ставится, курс остаётся «может вести», и при следующей сборке без «оставить принятое» преподаватель снова может смениться. Без `force` `accept` спрашивает (раздел 7.4): абзац `web.preview.confirm_teacher` со строкой «курс: прежний → новый» на каждый такой курс (`ranking.changedTeachers`), `web.preview.confirm_teacher_joint` на каждую линейку потока-копии этих курсов, `web.preview.confirm_over_limit`, если у кого-то курсов станет больше лимита (`variants.teacherOverLimit(settings, answer, stage, variant)` → `[(преподаватель, курсов, лимит)]`; `variant` — уже после `stages.lockedFromAnswer`, каким его сохранит принятие: курс, который стал зафиксированным после сборки, считается у преподавателя из расписания, а не из файла варианта; курсы других этапов по `stages.occupiedByOtherStages`, копия считается своим источником, плюс курсы варианта без копий; превышение из-за курсов «ведёт» и курсов, которые преподаватель ведёт и в принятом расписании, не считается). Сборка лимит соблюдает, поэтому такой абзац бывает, только если файл варианта правили или проект изменился после сборки. Занятость нового преподавателя на прежних часах копии проверяет `joint.copyConflicts` (причина `busy`).

**Варианты переписываются** вместе с расписанием (`project.rewriteVariants`), чтобы принятие старого варианта не вернуло то, что уже убрано:
- при удалении курсов (`purgeCourses`);
- при снятии преподавателя (`dropTeacherLessons`);
- при замене преподавателя (`replaceScheduledTeacher`).

| `teacherWorkDays` | 100 | каждый рабочий день преподавателя на этапе; дни, где он уже ведёт уроки других этапов, бесплатны (`teacher_busy_days`) | 0 | `teacherWorkDays` |
| `levelsApart` | 300 | урок пары уровней ЕГЭ одного предмета без пары в то же время | 0 | `levelsApart` |
| `pairsSameDay` | 100 | день, где стоят оба курса пары «сдают вместе» (кроме `COMMON_SUBJECTS`: русский, математика, математика база) | 0 | `pairsSameDay` |

**Где используются:**
- **Движок** — `struct Weights` в `solve.cpp`, `Weights::init`. Незнакомые ключи игнорируются. `equalLessons` = 1e6 (два урока курса в день) и `missingLesson` = 2e6 (непоставленный урок) зашиты в движок, из файла не читаются. Цена смены преподавателя `teacherChange` (ход 4, раздел 6.4) тоже не ключ файла: движок берёт половину НОД всех цен > 0 среди семи весов и цен своих правил (при весах по умолчанию НОД = 10, цена 5; без цен — 0,5; если какая-то цена не целая — половину самой лёгкой). При целых ценах любая разность энергий кратна НОД, поэтому любой настоящий выигрыш смены больше цены.
- **Оценка вариантов** — `variants.variantMetrics` → `variantTotal`: `total` = Σ (число нарушений × вес) + свои правила × их `weight`. Внимание: веса, которого нет в `weights.json`, Python считает **нулём**, а движок берёт своё значение по умолчанию (столбец «движок без ключа»; у трёх первых строк оно не 0). На практике это не проявляется, потому что `prepareProject` дописывает недостающие ключи из шаблона. Строки `missing`, `equalLessons` и `teacherClash` — обязательные правила (`HARD_METRICS`), в `total` не входят. Порядок вариантов задаёт `variants.variantScore`: (сумма HARD, total).
- **Страница** — `state.weights` (файл проекта) и `state.weightDefaults` (шаблон: от него считаются деления ползунков). Порядок пунктов — `variants.WEIGHT_ORDER`, отдаётся через `/api/meta.weightOrder`.
- **Запись** — из интерфейса только `tabs/run.setWeight`: только существующие ключи, значение — `project.number`, целое в [0, 2³¹−1] (вне границ — прижимается). Кроме того, файл пишут `tree.repairWeights` (создание из шаблона, дописывание ключей) и `versions.restoreVersion` (копия из версии).

Новый вес добавляется в четыре места: шаблон `src/files/weights.json`, `variants.WEIGHT_ORDER`, `variants.METRICS` и `struct Weights` в `solve.cpp`, после чего `solve.exe` нужно пересобрать. Ключи всех четырёх мест (в `solve.cpp` — строки `data.value("<вес>", …)` в `Weights::init`) и подписи к ним в `ru.hjson` сверяет тест `tests/test_functions_variants.py` (`WeightKeysTests`).

## 6. Вход и выход движка `solve.exe`

### 6.1. Как сервер запускает движок

`src/web/build.py`, `runJob`:
1. Под `LOCK` читаются `settings`, `answer` и `weights` проекта.
2. В папку `%TEMP%\schedule-build-*\` (`_tempFolder`) **один раз на сборку** пишутся `input.json` = `solver_input.buildStageSettings(settings, answer, stage, keep, weights)` и `weights.json` = копия весов проекта (`_prepareInput`). Веса нужны и во входе: по ним мягкие правила с курсами-копиями становятся ценами слотов (раздел 6.2). Все варианты одной сборки строятся по одним данным. Пока сборка идёт, менять эти данные нельзя: и сетку, курсы, преподавателей, и веса, свои правила, тщательность, число вариантов, лимит курсов и пары предметов (раздел 7.4).
3. На каждый вариант — отдельный процесс (`_runSolver`). Перед запуском удаляется старый `output.json`. Командная строка:
   ```
   src\modules\solve.exe --weights <tmp>\weights.json --input <tmp>\input.json --output <tmp>\output.json --iterations <settings.iterations | 10000000>
   ```
   Путь к движку относительный (`build.SOLVER`): сервер работает из корня программы, это обеспечивает `web.py`. Процесс запускается без окна, stderr сливается в stdout, процесс привязан к Job Object программы (`closeWithProgram`).
4. Код 0, сборку не остановили и есть `output.json` → вариант сохраняется (`_storeVariant`, под `LOCK`). Если этап тем временем исчез из проекта, вариант не сохраняется.
5. Временная папка удаляется с повторами (`_removeFolder`: до `CLEANUP_ATTEMPTS` = 10 попыток с паузой 0,2 с, потому что сразу после «Остановить» Windows ещё держит файлы снятого решателя). Не удалилась — в `app.log` пишется предупреждение, а сборка ошибкой не считается.

### 6.2. Вход: `buildStageSettings`

Вход — **глубокая копия `settings.json`**, урезанная до курсов одного этапа и дополненная служебными ключами. Проверено на копии: ключи входа = ключи `settings` + `blocked_slots`, `custom_penalties_compiled`, `existing_courses_by_teacher`, `teacher_busy_days`, `keep_teacher_courses`. Ключ `custom_penalties` попадает в копию, если он есть в файле, но движок его не читает.

| ключ входа | откуда | что в нём |
|---|---|---|
| `classes.custom_groups`, `classes.lessons`, `constants` | `stageOnly` по `solverGroups` | только курсы этапа, кроме курсов-копий (раздел 3.12) |
| `constants` (дополнение) | `pinStartedCourses` по плану `pinPlan` | уроки идущих курсов и курсов из `keep` |
| `classes` (без части курсов) | `blockFixedCourses` | идущие курсы **без преподавателя** выброшены совсем; их уроки сервер переносит в варианты сам. Курсов-копий во входе нет с самого начала, их уроки сервер тоже переносит в варианты сам |
| `teachers[имя]` | `flattenAvailability` | **другой вид**, чем в `settings` (см. ниже) |
| `blocked_slots` | `programBlockedSlots` + `blockFixedCourses` | `{курс: [[день, урок]]}` — где курсу стоять нельзя: дыры сетки, уроки «непересекающейся» программы того же предмета в других этапах и у копий этого этапа, время выброшенных курсов и копий, с которыми нельзя совпадать (пара «нельзя» в одной линейке, непересекающиеся программы). Курсы без запретов в словарь не попадают. |
| `existing_courses_by_teacher` | `stages.occupiedByOtherStages` | `{преподаватель: сколько курсов других этапов (пересекающихся по датам) и копий этого этапа}` — для лимита курсов. Источник и его копия — один курс |
| `teacher_busy_days` | то же | `{преподаватель: [дни]}`, где он уже ведёт уроки других этапов и копий этого этапа |
| `custom_penalties_compiled` | `penalties.compilePenalties` + `solver_input.sameDayPairs` + `priceFixedNeighbours` | см. ниже |
| `keep_teacher_courses` | `solver_input.keepTeacherCourses` по `joint.jointCopies` | `[курс]` — курсы входа, к которым присоединяется более поздний поток (источники общих уроков), в порядке курсов входа. Им движок не меняет преподавателя при подборе (ход 4, раздел 6.4): «не может» и занятость преподавателя в потоке-копии он не видит. Пишется всегда; без копий — `[]`. Ключ необязательный: нет ключа — движок считает список пустым, прежний `solve.exe` его не читает |
| `working_days_per_week`, `max_lesson_count_per_day`, `max_courses_per_teacher`, `subjects`, `joint_subject_pairs`, `soft_subject_pairs`, `non_overlapping_programs` | как в `settings` | |

**Вид преподавателя во входе:**

```json
{"subjects": [{"subject": …, "classes": [курсы этапа], "assigned": [курсы этапа]}],
 "free": [[d, l]], "possible": [[d, l]]}
```

- `availability` удалена;
- `free` = «не может» этапа + уроки других этапов в пересекающиеся даты + уроки копий этого этапа (при любых датах источника) + закрепления его `assigned`-курсов из других этапов + `missingSlots`. Закрепления берутся из `stages.pinnedForTeacher`: `{(день, урок): [курсы]}`, в одном слоте может быть несколько курсов. Слот попадает в `free`, только если среди них есть курс **не** из этого этапа: закреплённые уроки своих курсов этапа решатель ставит сам. Закрепления источников копий этапа учитываются при любых датах (копия встанет в их часы), закрепления самих копий — нет;
- уроки копий **других** этапов, чей источник в строящемся этапе, преподавателя не занимают (`occupiedByOtherStages` их пропускает): это уроки самого этапа, их можно оставить на месте или сдвинуть;
- `classes` и `assigned` обрезаны до курсов этапа;
- у начавшихся курсов и курсов из `keep` «ведёт» — преподаватель с их уроков в `answer.json` (первый найденный, через `courses.assignTeacher`), если он ещё есть в проекте. Поэтому смена преподавателя в подборе (ход 4) их не трогает. Если его нет: начавшийся курс выбрасывается из входа (решает `pinPlan`, из входа убирает `blockFixedCourses`), а его время запрещено остальным, а курс только из `keep` остаётся, и преподавателя ему выбирает решатель;
- во входе — **все** преподаватели проекта, не только те, у кого есть курсы этапа.

**`custom_penalties_compiled`:**
- `class_slots`: `{курс: [[день, урок, цена]]}`;
- `teacher_slots`: `{преподаватель: [[день, урок, цена]]}`;
- `teacher_daily`: `{преподаватель: [[лимит, цена]]}`;
- `group_daily`: `[{"classes": [курсы], "limit", "weight"}]`; курс, записанный в группу дважды, движок учитывает один раз;
- `adjacent`: `{курс: цена}`;
- `same_day`: `[{"a", "b", "weight"}]`;
- `same_day_pairs`: `[[курс, курс]]` — пары «в разные дни», цену берёт из `weights.pairsSameDay`.

Все семь ключей есть всегда (пустые, если правил нет). Правила с весом ≤ 0 не компилируются. Свои правила компилируются по курсам этапа без копий (`penalties.penaltyGroups`), включая выброшенные идущие курсы; движок молча пропускает записи о курсах, которых нет во входе. `same_day_pairs` считается уже по курсам входа.

**Мягкие правила с неподвижными курсами** (`solver_input.priceFixedNeighbours`). Неподвижные курсы — это курсы-копии этапа и выброшенные идущие курсы без преподавателя (`blockFixedCourses`): их уроки стоят в расписании и переносятся в каждый вариант, а во входе их нет. Поэтому решатель сам не видит, что сосед стоит одновременно с таким курсом. Вместо этого его соседям дописываются цены в `class_slots`, с весами из `weights.json` (аргумент `weights` у `buildStageSettings`). Ниже такой курс для краткости — «копия»:
- «нежелательно» (`softSubjectPair`) — курсу той же линейки потока с парой «нежелательно» к предмету копии: цена в слотах копии;
- «уровни врозь» (`levelsApart`) — тому же предмету на другом уровне ЕГЭ: цена во всех слотах сетки, кроме слотов копии. Движок считает min(уроков, уроков копии) − общих слотов, цена за урок вне слотов копии отличается от этого на постоянную величину, поэтому выбор ходов тот же;
- «пары не в один день» (`pairsSameDay`) — предметам, которые сдают вместе (`pairs.sameDayMatters`): цена в каждом слоте дней копии.

Курс без уроков (копия ждёт поток-источник) и вес 0 цен не дают; без `weights` их нет совсем. Уроки копий движок получает прежними ключами (`free`, `blocked_slots`, `existing_courses_by_teacher`, `teacher_busy_days`, `class_slots`); для источников копий добавлен один новый ключ `keep_teacher_courses` (раздел 6.4, ход 4).

**Режим keep** («оставить принятое»): `keep` = курсы этапа без копий, которые уже есть в `answer.json` (`solver_input.keepCourses`; тот же список берут сборка и прогноз в `state`). `tabs/run.run` выключает keep, если все уроки этапа, не считая копий, уже стоят.

**Что закрепляется — одно место, `solver_input.pinPlan`.** Он возвращает `(pins, drop)`: `pins` — `[(курс, предмет, [(день, урок)], преподаватель или None)]`, все уроки из `answer.json` у идущих курсов и курсов из `keep`; `drop` — начавшиеся курсы, у которых преподавателя нет. План применяет `pinStartedCourses` (вход решателя), по нему же считают:
- `pinForecast(settings, answer, stage, keep=(), context=None)` → `{pinned, total, free, noTeacher}` — прогноз до сборки. `total` (M) — часы курсов этапа без `drop`; `noTeacher` (X) — часы тех из них, кого никто не может вести (`courses.courseCandidates` пуст, а преподавателя из расписания, который во входе решателя «ведёт» курс, нет или у него нет этого предмета) — решатель их уроки не ставит, даже закреплённые; `pinned` (N) — у остальных по каждому курсу и предмету: у курса из `pins` — `min(часы, |уроки из pins ∪ ручные закрепления, которые останутся во входе| − те из них, что решатель не поставит)` (`solver_input.plannedPins`, `stages.pinConflicts`, раздел 4: их он назовёт не вставшими закреплениями), у остальных — `min(часы, |ручные закрепления|)` (помехи им прогноз не ищет); `free = total − pinned − noTeacher` (K). Решатель печатает те же N, M, K и X в строке «Закреплено N из M уроков, подбирается K[, без преподавателя (не ставятся): X]» (раздел 6.4), если все закрепления встали; не вставшее закрепление он называет строкой `[Внимание] закреплённый урок … не поставлен: …` и считает подбираемым. Курсы, которым преподаватель не достанется из-за лимита курсов, решатель узнаёт только при подборе и тоже относит к X; прогноз считает их в `free`. Совпадение чисел проверяют `tests/test_functions_solver_input.py` (`test_solver_prints_the_same_numbers`, `test_solver_counts_rejected_pins` — когда закрепления идущего курса встают не все) и `tests/test_web_tab_run.py` (`test_forecast_matches_solver_line`) на настоящем `solve.exe`, в том числе с курсом, который некому вести;
- `droppedLessons(settings, answer, stage)` — сколько уроков у курсов `drop`: их сервер переносит в варианты как есть (строка `web.run.carried_no_teacher`).

**Что движок читает из входа** (`solve.cpp`, класс `Data`): `working_days_per_week`, `max_lesson_count_per_day`, `max_courses_per_teacher`, `subjects[i][0]`, `classes.custom_groups[*]` (`name`, `program`, `line`, `stream_id`), `classes.lessons`, `teachers[*]` (`free`, `possible`, `subjects[*].subject/classes/assigned`), `constants`, `joint_subject_pairs`, `soft_subject_pairs`, `non_overlapping_programs`, `blocked_slots`, `existing_courses_by_teacher`, `teacher_busy_days`, `custom_penalties_compiled`, `keep_teacher_courses`. Остальные ключи игнорирует.

Слот внутри движка = `день × MAX_LESSON_IN_DAY + урок`.

Что движок делает с плохими данными:
- неизвестный предмет в `joint_subject_pairs` и плохой ключ, слот вне недели или неизвестный предмет в `constants` — строка `[WARNING] …`, запись пропускается;
- неизвестный предмет в `soft_subject_pairs` — запись пропускается **молча**; `non_overlapping_programs` не проверяется вовсе (пара просто ни с чем не совпадёт);
- предмет курса с ненулевой нагрузкой, но без кандидатов в `classes` — строка `[Внимание] …: нет преподавателя…`, этот предмет курса не планируется;
- обязательны (иначе исключение nlohmann::json и код не 0): числа `working_days_per_week` и `max_lesson_count_per_day`, объект `classes`, строка `subject` в каждом `teachers[*].subjects[*]`; нагрузка в `classes.lessons` — целые числа. Отсутствующие `teachers`, `subjects`, `constants` движок переносит как пустые.

### 6.3. Флаги командной строки

| флаг | по умолчанию в движке | передаёт сервер |
|---|---|---|
| `--input <файл>` | `settings.json` | да |
| `--output <файл>` | `answer.json` | да |
| `--weights <файл>` | веса из `struct Weights` | да |
| `--iterations <N>` | 50 000 000 | да: `settings.iterations` или 10 000 000 |
| `--seed <целое>` | 0 = случайное зерно | нет: каждый вариант получает своё зерно |
| `--t0`, `--tend <дробное>` | 0 = по весам: t0 = 0,4 × наибольший вес, не меньше 100; tend = min(1, t0), так же и при tend > t0 | нет |
| `--cycle <N>` | 5 000 000 шагов в цикле; 0 или больше `--iterations` = один цикл. Если `--iterations` не делится на цикл, циклы делаются равными и чуть короче: ⌈iterations / ⌈iterations / cycle⌉⌉, чтобы последний тоже остыл до tend (при 10, 30 и 100 млн шагов цикл остаётся 5 млн; при 3 млн, «Быстро», цикл длиннее прогона, поэтому весь прогон — один цикл) | нет |
| `--cycle-from-best <0\|1>` | 1 | нет |

Флаги, которые сервер не передаёт, нужны тестам движка (`tests/engine.py`) и экспериментам.

Смена преподавателя (ход 4) новых флагов не добавила. Отладочная проверка энергии — не флаг, а отдельная сборка `solve.cpp` с `-DCHECK_ENERGY` (её собирает во временную папку `tests/test_engine_swap_check.py`, без g++ тест пропускается). Она раз в 50 000 шагов и после возврата к лучшему сравнивает энергию по частям с полным пересчётом и проверяет состояние хода 4, а в конце печатает одну строку `CHECK checks=… bad=… badState=… maxDiff=… limitRejects=…`. В `solve.exe` для завуча (`compile.bat`, `build.bat`) и в архив передачи она не попадает.

### 6.4. Выход и коды выхода

- **`--output`**: `{курс: [день][урок] → {"subject", "teachers": [один преподаватель]}}`, пустая ячейка — `{"subject": "#", "teachers": []}`. Неделя прямоугольная: `working_days_per_week × MAX_LESSON_IN_DAY`. В ответе есть **каждый** курс входа, даже без единого урока (тогда вся неделя из `"#"`). Файл пишется с отступом 4.
- **Код 0** — готово. Ответ пишется, **даже если часть уроков не поставлена**: их число сервер узнаёт по метрике `missing`.
- **Код не 0** — неверная командная строка (CLI11) либо нечитаемый или испорченный вход или файл весов (исключение). Сервер пишет строку `web.run.solver_failed` с кодом, вариант не сохраняется.

**Строки хода работы** (stdout, UTF-8, без буфера). Сервер читает их построчно (`build._runSolver`), а уровень определяет `build._solverLineLevel` по `SOLVER_LINE_LEVELS`:

| начало строки | уровень |
|---|---|
| `[Внимание] …` | `warn` (сообщения человеку по-русски) |
| `[WARNING] …` | `warn` (технические) |
| `Шаг N из M \| …` | `progress` |
| остальное, например `Готово: оценено изменений N из S шагов` | `text` |

Строки движка по порядку (кроме предупреждений `[Внимание]` / `[WARNING]`, которые бывают при чтении входа, выборе преподавателей и закреплениях):

| строка | когда | смысл |
|---|---|---|
| `Закреплено N из M уроков, подбирается K` и, если X > 0, `, без преподавателя (не ставятся): X` | всегда, сразу после закреплённых уроков | N — закрепления, которые встали; K — уроки, которые программа двигает (в том числе не вставшие закрепления); X — часы курсов без подходящего преподавателя или без свободного из-за лимита курсов; M = N + K + X. Прогноз сервера — `pinForecast` (раздел 6.2) |
| `Из неудобств E дают закреплённые уроки — программа их не двигает (…)` | E > 0 | часть энергии, которую дают одни закреплённые уроки: урок в выходной, час «может» у преподавателя, цена часа для курса и преподавателя. Цена часа курса — это и свои правила, и цены соседей неподвижных курсов (`priceFixedNeighbours`, раздел 6.2): во входе они не различаются, поэтому причина называется «свои правила или общие уроки присоединённой линейки». В скобках — только причины, которые есть. Считается так же, как в `totalEnergy` (`printPinnedCost`) |
| `Подбирать нечего: все уроки закреплены, расписание оставлено как есть` | K = 0, X = 0, M > 0 | отжиг не запускается: строк «Шаг» нет, ответ пишется как обычно, код 0, итог — `Готово: оценено изменений 0 из 0 шагов`. При K = 0 печатается ровно одна из трёх строк «Подбирать нечего» |
| `Подбирать нечего: у незакреплённых уроков нет преподавателя` | K = 0, X > 0 | то же; закреплено не всё — остальные уроки (X) не ставятся. Так бывает и при N = 0: новый этап, где преподаватели ещё не отмечены |
| `Подбирать нечего: в этом потоке или блоке курсов нет уроков` | M = 0 | то же; во входе нет ни одного урока |
| `Подбирать почти нечего: варианты, скорее всего, совпадут` | 1 ≤ K ≤ 2 | предупреждение; совпавшие варианты сервер не сохраняет (раздел 4) |
| `Шаг N из M \| пары «нежелательно»: … \| 2 урока курса в день: … \| …` | раз в 1 млн шагов | состояние текущего расписания, в скобках — лучшее пока. Числа «неудобства» и «лучшее пока» — энергия движка: кроме цен правил в них есть непоставленные уроки (`missingLesson` = 2 млн за урок), два урока курса в день (`equalLessons` = 1 млн) и цена смены преподавателя (`teacherChange` × курсы, которые ведёт не выбранный до отжига). В «Итог» на «Предпросмотре» эти части не входят, поэтому числа больше «Итога»; если непоставленных уроков и двух уроков в день нет, разница — только цена смены. Первые две части строка показывает и отдельно («2 урока курса в день», «не поставлено уроков»), так что разница в миллионы — не ошибка |
| `Остановлено на шаге N из M: подбирается только K урок(а/ов), лучшее не менялось 1 млн шагов` | K ≤ 5 (`EARLY_STOP_LESSONS`) и лучшее не менялось 1 млн шагов (`EARLY_STOP_WINDOW`), проверка — при строке «Шаг» | ранний конец подбора: дальше строк «Шаг» нет, в ответ идёт лучшее расписание, код 0. Пороги — по замерам на потоке 2 с закреплениями (комментарий у констант в `solve.cpp`). При K > 5 подбор всегда идёт все шаги |
| `Готово: оценено изменений N из S шагов` | последняя | S — сколько шагов сделано на самом деле (меньше `--iterations` при раннем конце); N — ходы, которые прошли жёсткие правила и были оценены, в том числе смены преподавателя (ход 4); обычно заметно меньше S |

**Смена преподавателя в подборе (ход 4).** Кроме переноса урока, обмена двух уроков и вставки непоставленного урока, отжиг меняет преподавателя курса: все уроки курса по одному предмету, и поставленные, и непоставленные, отдаются другому преподавателю из «может вести» (`teachers[*].subjects[*].classes` входа). Клетки уроков не двигаются. Начальное состояние прежнее: преподаватель, выбранный жадно до отжига.
- **Кому меняет** (список курсов со сменой, один раз перед отжигом): курс без «ведёт», с преподавателем, с двумя кандидатами и больше; во входе нет `constants` по этому курсу и предмету (даже если закрепление не встало); курса нет в `keep_teacher_courses`; хотя бы у одного другого кандидата `existing_courses_by_teacher` + «ведёт» меньше `max_courses_per_teacher`. Курсы с «ведёт», идущие, из `keep` (они приходят с «ведёт», раздел 6.2), с закреплениями и источники общих уроков преподавателя не меняют.
- **Жёсткие правила:** у нового преподавателя курсов меньше лимита, и в каждой клетке курса он не «не может» и не занят. Такой отказ не входит в N строки «Готово».
- **Частота:** ход выбирается с вероятностью |курсов со сменой| / (20 × |пар «курс + предмет»|). Если курсов со сменой нет, лишнего случайного числа не берётся: ответ и журнал на том же зерне побайтно прежние (сторож — `tests/test_engine_swap.py`, эталоны `tests/fixtures/engine_compat/`). На входе с такими курсами ответы на тех же зёрнах другие.
- **Оценка:** Δ = изменение штрафов двух преподавателей («может», окна, рабочие дни, свои правила по преподавателю) плюс цена смены `teacherChange` (раздел 5) за курс, который ведёт не выбранный до отжига. Смена без выигрыша поэтому не делается. Новых метрик, весов и строк журнала нет; строки о «ведёт» сверх лимита, о максимуме курсов и о закреплениях печатаются до отжига и остаются верными, потому что ход закреплённые курсы не трогает.
- Лучшее состояние хранит вместе с расписанием и преподавателя каждого курса, и счётчики курсов.
- **Доводка после отжига:** лучшее часто запоминается в горячей части цикла вместе со сменой, принятой «в гору». Поэтому после возврата к лучшему движок без случайных чисел делает все смены с Δ < 0 (те же жёсткие правила), пока они есть, — в том числе возвращает выбранного до отжига, если смена ничего не дала. Затем пробует вернуть сразу два сменённых курса к выбранным до отжига (два уровня в одних клетках, обменявшиеся преподавателями, по одному не вернуть); возврат остаётся, если энергия уменьшилась и жёсткие правила и лимит соблюдены. В N строки «Готово» эти смены не входят. Без курсов со сменой доводка ничего не делает.

Строк «Шаг» может быть меньше, чем `--iterations` / 1 млн, или не быть вовсе; страница на них не опирается: полоса хода на «Запуске» считается по номеру варианта (`number` / `total` из `/job`).

До первого варианта сервер пишет (`build._explainPins`, уровень `text`): прогноз закреплений `web.run.pin_forecast`, а если `noTeacher` > 0 — `web.run.pin_forecast_no_teacher` (`solver_input.pinForecast`, поле `forecast` этапа в разделе 7.5; тот же текст у галочки на «Запуске») и, если есть идущие курсы без преподавателя, которых решатель не получает, — сколько их уроков переходит в варианты как есть (`web.run.carried_no_teacher`, `solver_input.droppedLessons`).

Служебные строки сервера `=== … ===` получают уровень `head`: начало варианта «…: Вариант N / T» (N — номер запуска), чем кончился запуск решателя, «Вариант N совпал с сохранённым вариантом M — не сохранён» (`web.run.variant_repeated`, M — номер на «Предпросмотре») и, когда после совпадения номер на «Предпросмотре» уже не равен номеру запуска, «Сохранён как вариант M» (`web.run.variant_saved_as`). Итог сборки (`build._summaryLine`): ни один из вариантов этапа принять нельзя (`build._noneAcceptable`: у каждого непустой `staleStarted` или `movedStarted`, раздел 4) — уровень `warn`, `menu.main.tab.run.variants_unacceptable` (проверяется первым; задание получает `unacceptable: true`, тост — `web.run.variants_unacceptable_short`); иначе есть сохранённые варианты — `done`: сохранён один, а остальные совпали с ним — `menu.main.tab.run.variants_all_same` (проверяется вторым, и для остановленной сборки тоже); сохранено больше одного и часть совпала — `menu.main.tab.run.variants_ready_repeated`; иначе «Готово вариантов: N…». Тост на странице берёт короткие тексты `web.run.*_short` с той же развилкой (`run.js`). Остановлена без новых вариантов — `head`, текст `web.run.stopped_kept` (а если прежних вариантов этапа нет — `web.run.stopped_none`); не получилось ни одного — `head`, `menu.main.tab.run.no_variants`. Если сборка упала в самом Python (например, не запустился `solve.exe`), последняя строка — текст `web.run.solver_failed` с кодом `?`, уровень `head`, подробности в `app.log`.

## 7. HTTP API между страницей и сервером

Сервер слушает только `127.0.0.1`, порт от 8765 до 8814 (`web.py`). На любой адрес с чужим `Host` отвечает 403 `{"error"}` (`core.onlyThisComputer`).

Страница обращается к серверу через одну функцию `api()` в `static/core.js`. При ошибке она бросает `Error` с текстом `error` и полем `code`.

### 7.1. Ошибки

| ответ | когда |
|---|---|
| 400 `{"error": текст, "code"?: "no_project"}` | `UserError`: понятная ошибка. `code` = `"no_project"`, если проекта нет (`project.projectPath`). Страница тогда закрывает проект. |
| 400 `{"error": текст}` | `ValueError("web.…")`: повреждённый файл и т. п. Текст — перевод ключа. |

| 403 `{"error": web.error.wrong_host}` | заголовок `Host` не `127.0.0.1`, `localhost` или `[::1]` |

### 7.3. Протокол действий

Все изменения проекта идут через `POST /api/project/<p>/action` с телом `{"action": имя, "args": {…}}` (`actions.doAction`). Имя действия — это имя функции с `@action`; переименовывать его нельзя. Аргументы передаются как именованные параметры функции. Лишний или неверный аргумент даёт общую ошибку (`TypeError` → `UserError`).

**Как обрабатывается запрос:**
1. Тело не объект, имя не строка или неизвестно → 400 `web.error.generic`.
2. Под `LOCK`: если идёт сборка, а действие помечено `@action(blocking=True)` (`BLOCKED_WHILE_RUNNING`) → 400 `web.error.busy`.
3. Ответ действия (dict или `None`) **всегда дополняется полем `state`**.

**Варианты ответа:**

| ответ | значит | что делает страница (`core.js`, `doAct`) |
|---|---|---|
| `{state}` | сделано молча | перерисовывает |
| `{confirm, yes?, danger?, state}` | нужно подтверждение, **ничего не изменено** | спрашивает и при согласии повторяет то же действие с `args.force = true`. `yes` — надпись кнопки; его может не быть (например, вопрос `setTeacher` о занятом преподавателе), тогда кнопка «Да» (`web.common.yes`) |
| `{notice, state}` | только объяснение, ничего не изменено (нужно выбрать другое) | окно, которое надо закрыть |
| `{message, state}` | сделано, есть пояснение | всплывающее сообщение |
| `{error, code?}` (400) | ошибка | сообщение об ошибке |

`newStream` дополнительно возвращает `section`: номер нового потока. Если в ответе есть и `notice`, и `confirm`, страница обрабатывает только `notice`; `message` показывается, только если нет `confirm`.

**Типы аргументов.** `section` — **число** для потока и строка (`"extra"`, `"may"`, `"summer"`) для блока: `project.requireSection` сравнивает с int из `stream_id`. `stage` — всегда строка-ключ этапа. Слоты — пары целых `[день, урок]`.

Если удаляемые курсы (`deleteStream`, `deleteLine`, `deleteCourse`) — источники, в вопросе есть абзац `web.classes.joint_remove_note`: какие копии станут обычными курсами, их уроки останутся. Перечень идущих курсов в этом вопросе (`web.confirm_remove_started`) — только курсы, которые начались сами (`startedCourses(…, shared=False)`): источник, который «идёт» лишь через копию, туда не попадает — его поток ещё не начался, а уроки копии останутся.

**`setJoint`** — отметка «Присоединяется к» у линейки потока (раздел 3.12). Сначала `joint.setJointLine` пробно вызывается на копиях `settings` и `answer`: при отказе или «Отмене» файлы не меняются.
- Отказы (ошибка, ничего не изменено): блок, нет такой линейки, поток не раньше своего, в нём нет линейки или в ней нет ни одного такого же предмета (`joint.jointOptions`) — `web.error.joint_source`; выбранный поток сам идёт вместе с Потоком N — `joint_chain`; с этой линейкой уже идёт другой поток — `joint_has_copies`; пропали бы или сменились уроки курса, который уже идёт, — `joint_started`. Нет раздела или линейки — как у остальных действий (`requireLine`).
- Включение, когда у будущих копий в расписании другие уроки, без `force` — confirm (кнопка «Да», `tabs/classes.jointLessonParagraphs`) с абзацами по тому, что станет с уроками этих курсов: встанут в дни и часы источника — `web.classes.joint_confirm` (`{line}`, `{stream}`, `{number}`); у источника уроков нет, копия их ждёт и свои уроки теряет — `web.classes.joint_confirm_waiting` (`{courses}`, `{line}`, `{stream}`, `{number}`); при смене источника бывшая копия становится обычной и теряет общие уроки — `web.classes.joint_confirm_dropped` (те же поля). Если уроки меняются, в конце вопроса — `web.classes.joint_version` (перед изменением сохранится версия); в `joint_confirm` этой фразы нет. Уроков нет или они уже такие же — без вопроса и без версии.
- Включение, когда уроки источника встают в новые для копии часы, где мешают другим урокам в её даты (`joint.copyConflicts`: курсы любого этапа, которые идут в даты копии, кроме курсов, уроки которых задаёт этап источника; преподаватель занят, пара «нельзя», программы, которые не пересекаются), без `force` — confirm с абзацем `web.classes.joint_conflicts` (`{line}`, `{stream}`, `{conflicts}`, `{stages}` — этапы, где стоят мешающие уроки, `project.conflictStages`; вместе с `joint_confirm`, если нужен и он). На местах, где копия уже стояла, проверяется только, не занят ли преподаватель, которого там у неё не было (причина `busy`); тот же урок с тем же преподавателем не проверяется.
- Включение, когда общие уроки встают во время, где у их преподавателя на этапе этого потока «не может» (`joint.copyCannot`), без `force` — в том же confirm абзац `web.classes.joint_cannot` на каждого такого преподавателя (`{teacher}`, его время `{slots}` через «; », `{line}`, `{stream}`; `project.cannotParagraphs`). Названы все уроки новых копий и копий, у которых сменился источник (выбрали другой поток), даже если урок у того же преподавателя уже стоял там до отметки: курс тогда был обычным или стоял в часы другого потока, и предупреждения о нём не было. Это не запрет: с `force` отметка ставится, версии нет, если уроки не менялись.
- Если уроки в расписании меняются — версия «Перед: …» (`web.version.joint` или при снятии `web.version.joint_off`).
- Затем `saveSettings` (первым), `saveAnswer(project, answer, settings)` и удаление вариантов этапа этого потока — всегда.
- Смена источника (линейка уже идёт вместе с Потоком N, выбрали другой поток): бывшие копии, предмета которых в новом источнике нет, становятся обычными курсами и теряют уроки (входят в изменённые — значит, версия «Перед: …»; если такой курс уже идёт — отказ `joint_started`).
- Снятие (`source = null`) убирает поле у всей линейки и уроки бывших копий, отвечает message `web.classes.joint_off`. Включение отвечает message `web.classes.joint_on`. Повторное включение с тем же потоком делает копиями предметы, которые появились в линейке-источнике после отметки (на странице — кнопка «Присоединить к Потоку N» у такого курса).

### 7.6. `/variants`

```
{build: str, variants: [вариант], allTied: bool, teacherCourses: [курс], metrics: [ключи METRICS],
 hard: [HARD_METRICS], limit: int, penalties: [правило + description]}
```

`teacherCourses` — строки блока «Кто ведёт» в таблице вариантов и в Excel (`variants.teacherCourses`): курсы, у которых преподаватель различается между не отклонёнными вариантами (по полю `teachers`) или есть в `teacherChanges` хотя бы одного не отклонённого варианта. Порядок — как в проекте; страница идёт по этому списку, а не по ключам `teachers` (Flask отдаёт их по алфавиту). Курс, которого нет в каком-то варианте, по этому варианту не сравнивается. Пустой список — блока нет. У заголовка блока «i» с пояснением жёлтой ячейки (`web.preview.teachers_hint`).

`build` — отметка сборки (`ranking.variantsBuild`): наибольшее mtime файлов `<N>.json` строкой (дробное число секунд, например `"1791173471.5247362"`); `""` — папки вариантов этапа нет, `"0"` — папка есть, а файлов вариантов в ней нет (проверено запуском). Варианты отсортированы от лучшего (`variants.rankVariants`): сначала варианты, которые можно принять, потом те, что принять нельзя (`variants.unacceptable`: непустой `staleStarted` или `movedStarted`); внутри — по `variants.variantScore` (обязательные правила, потом итог), при равной оценке — по номеру. `allTied` (`variants.allTied`) — все не отклонённые варианты (их больше одного) в «ничьей» (`tied`): страница пишет `web.preview.all_equal` («можно принять любой»); при не отклонённом варианте, который принять нельзя, — `false`.

**Поля варианта** (`ranking.rankedVariants`):

| поле | смысл |
|---|---|
| `number` | номер файла |
| `answer` | сам вариант; курсы-копии этапа в нём — с нынешними уроками источников из `answer.json` (`joint.followSources`), а зафиксированные курсы этапа — с уроками из `answer.json` (`stages.lockedFromAnswer`: курс мог стать зафиксированным после сборки), а не с теми, что были при сборке: так вариант и примется |
| `metrics` | `{missing, equalLessons, teacherClash, softSubjectPair, pairsSameDay, teacherPossibleSlot, teacherFreeTime, teacherWorkDays, weekend, levelsApart, custom: {id: число}, total}` (`variants.variantMetrics`). `teacherClash` (`variants.teacherClashCount`) — уроки варианта в часы уроков того же преподавателя в других этапах плюс накладки внутри этапа (`variants.stageTeacherClashes`: один преподаватель в одно время на двух своих курсах этапа, без копий; в слоте с N курсами лишних уроков N − 1). Решатель внутри этапа накладок не ставит; они бывают после `stages.lockedFromAnswer`: курс начался после сборки, вариант сменил ему преподавателя, и освободившееся время вариант отдал этому же преподавателю на другом курсе. Уроки копий этапа не дают `missing`, `teacherClash`, `teacherPossibleSlot`, новых рабочих дней и «окон» преподавателя; `softSubjectPair`, `pairsSameDay` и `levelsApart` считаются с копиями |
| `best` | первый не отклонённый из тех, что можно принять (пустые `staleStarted` и `movedStarted`, `variants.unacceptable`), после сортировки; если таких нет — ни у одного |
| `tied` | у варианта та же оценка, что у лучшего, и таких не отклонённых и тех, что можно принять, несколько |
| `accepted` | вариант стоит в расписании **и** его номер в `accepted.json`; копии этапа не сравниваются (`variants.isAccepted(answer, variant, courses, settings=…)`) |
| `same` | совпадает с расписанием, но принимали не его |
| `rejected` | номер в `rejected.json` |
| `problems` | `[{course, subject, expected, placed, teachers, reason}]`. Если `missing` > 0 — недостающие уроки, `reason` ∈ `no_teacher`, `limit`, `no_time`, `rules`; `teachers` — `[]` при `no_teacher`, имена при `limit`, `[[имя, свободных часов]]` при `no_time` и `rules` (`variants.missingDetails`; вход строится заново без keep, поэтому причины приблизительные). Кроме того, при любом `missing` — копии этапа, которые ждут поток-источник: `reason` = `joint_waiting`, `placed` = 0, `teachers` = `[]` и поле `number` — номер потока-источника (`variants.waitingDetails`) |
| `moved` | сколько уже принятых уроков вариант переставит; копии не в счёт |
| `jointMoved` | `[{line, number, lessons}]` — общие уроки потоков-копий, которые сдвинет принятие варианта (`ranking.jointMoved`): по записи на линейку потока-копии, `number` — номер потока-копии, `lessons` — сколько её уроков сдвинется. Считаются только источники, которые принятие может менять (`stages.changeableCourses`): у зафиксированного источника сдвига нет |
| `issues` | `{курс: {"день-урок": [строка \| {"text", "level": "warn"}]}}` (`variants.lessonIssues`); у курсов-копий подписей нет — их время задаёт поток-источник. Накладка внутри этапа (`variants.stageTeacherClashes`) подписана у каждого её урока: `web.issue.teacher_twice` (`{name}` — преподаватель, `{courses}` — другие курсы в это время через запятую) |
| `teachers` | `{курс: [имена]}` — кто ведёт курсы этапа в варианте (`ranking.variantTeachers`): курсы этапа без копий, только с уроками и преподавателем; имена в порядке первого появления в неделе курса. Варианты могут отличаться только преподавателями (смена преподавателя в подборе, раздел 6.4): такие варианты сохраняются оба (`build._storeVariant` сравнивает файлы целиком) |
| `teacherChanges` | `[{course, subject, before: [имена], after: [имена]}]` — кому из уже принятых курсов вариант сменит преподавателя (`ranking.changedTeachers`): курсы `stages.changeableCourses` (без зафиксированных — идут и все уроки на месте — и копий), по каждому предмету, `before` — из `answer.json`, `after` — из варианта, смена — когда множества имён разные. Курс, которого нет в расписании или в варианте, и уроки без преподавателя в расписании сменой не считаются. Уроки без преподавателя в варианте при принятом преподавателе — смена с `after: []` (выбранного сборкой преподавателя удалили или запретили ему курс, и варианты переписаны без него). У принятого варианта — `[]`. Страница по нему выделяет ячейку «Кто ведёт» (подсказка `web.preview.teacher_now`), пишет значок `web.preview.teacher_changes` у непринятого варианта и метку `web.preview.teacher_new` на карточках уроков этого курса и предмета |
| `staleStarted` | `[курс]` — идущие курсы этапа, которым вариант, собранный до их начала, сдвинул бы уроки или сменил преподавателя (`stages.staleStarted`, раздел 4). Непустой — `accept` такой вариант не примет (ошибка `web.error.variant_stale_started`, `force` не помогает): сервер и страница судят одинаково. Такой вариант стоит после остальных, у него нет `best` и `tied`; страница выбирает его сама, только если других нет, помечает «нельзя принять» и пишет под таблицей и в подсказке «Принять» `web.preview.cannot_accept` с причиной `web.preview.stale_started`. Курсы из `started.json` (шли уже при сборке) с теми же уроками, что на начало сборки, сюда не попадают — их проверяет `movedStarted` |
| `movedStarted` | `[{"course": курс, "lines": ["день и час: причина"]}]` — курсы, которые шли уже при сборке, а вариант всё равно сдвинул им урок или сменил преподавателя (`stages.movedStarted`, `project.movedStartedItems`, раздел 4). Непустой — `accept` не примет (`web.error.variant_moved_started`, `force` не помогает); порядок, `best`, `tied` и пометки — как у непустого `staleStarted`, под таблицей и в подсказке «Принять» — `web.preview.cannot_accept` с причиной `web.preview.moved_started` |

### 7.7. `/teacher`

`teacher_card.teacherCard`:
- `busy` — «не может» этапа, `[[d, l]]`;
- `possible` — «может», `[[d, l]]`;
- `commitments` — `[[d, l, "busy"|"pinned"|"joint", курс]]` (`stages.teacherCommitments`). Вид `"joint"` — общий урок: у преподавателя в этой клетке урок курса-копии этого этапа, курс — его источник (закрепление того же источника второй раз не называется). Это не «занят» уроком другого потока и не отметка, которую можно менять;
- `own` — `[[d, l, курс, идёт?]]`;
- `clashes` — `[[d, l, [курсы]]]`; общий урок источника и копии здесь не накладка;
- `subjects` — `[{subject, courses: [{name, stage, line, state, scheduled, started, orphan, joint}]}]`; `joint` у курса-копии — `{number, source}` (номер потока-источника и курс-источник), у остальных `null`. Отношение преподавателя к копии меняется только у источника (`cycleCourse` отвечает `web.error.joint_locked`);
- `limit`.

### 7.8. `/job`

`null`, если сборок не было с запуска сервера. Иначе `build.jobState`:

```
{running, stage, number, total, saved, repeats, stopped, seconds, unacceptable, log: [{text, level}]}
```

`saved` — сколько вариантов сохранено (номера 1…`saved`), `repeats` — сколько вариантов совпали с уже сохранёнными в этой сборке и не сохранены. `unacceptable` — итог сборки сказал, что ни один вариант принять нельзя (`build._summaryLine`, раздел 6.4); страница тогда показывает тост `web.run.variants_unacceptable_short`.

`level` ∈ `head`, `done`, `warn`, `progress`, `text` (`build.LOG_LEVELS`). `stage` — ключ этапа строкой, `number` — какой вариант строится (0 до первого), `seconds` — целое. Отдаются последние 400 строк (`LOG_SHOWN`), в памяти хранится до 2000 (`LOG_KEEP`). Задания живут только в памяти (`build.JOBS`); удаление проекта забывает его задание (`build.forget`).

### 7.9. Выгрузки `/export/<вид>`

| вид | файл | условие |
|---|---|---|
| `project` | `<проект>.zip` — вся папка проекта, пути относительно её корня (`tree.exportProjectArchive`); такой архив принимает импорт | — |
| `courses` | `<проект>-курсы.xlsx` | нужно непустое расписание |
| `teachers` | `<проект>-преподаватели.xlsx` | то же |
| `calendar` | `<проект>-календарь.xlsx` | то же; неверные даты курсов → понятная ошибка |
| `teacher_list` | `<проект>-преподаватели-список.xlsx` | расписание не обязательно |
| `variants?stage=` | `<проект>-варианты-<Этап>.xlsx` | этап существует (иначе `web.error.generic`) и есть варианты (иначе `web.export_variants.none`, «Вариантов пока нет…») |

Имена файлов берутся из `ru.hjson` и отдаются в `Content-Disposition` (`filename*=UTF-8''…`). Книги собирает `src/modules/functions/export.py`. Неверная дата курса или календаря даёт `export.CourseDatesError` (её бросает `export.parseDate`); сервер превращает в понятную ошибку только её, другие ошибки сборки книги под неё не маскируются. На листе варианта урок подписан линейкой курса так, как её показывает вкладка «Курсы» (`courses.lineOf`, `export.variantCells`): у семинара — «Семинар ОГЭ», а не общая программа «Семинары».

Общие уроки (раздел 3.12) в книгах подписаны (`export.jointNotes`): в «Курсах», «Календаре» и на листах вариантов у копии — «вместе с Потоком N», у источника — «вместе с Потоком M» (или «вместе с Потоками 2 и 3»). В «Преподавателях» общий урок — одна строка с пометкой «Потоки 1 и 2», не накладка. В «Списке преподавателей» общий курс и его урок посчитаны один раз. События копии в «Календаре» идут со своими датами.

Книга вариантов повторяет «Предпросмотр» (`export.variantsWorkbook`): на листе сравнения у вариантов пометки «лучший», «одинаково», «принят», «как сейчас» (`web.preview.same`, поле `same`), «отклонён» и «нельзя принять» (`web.export_variants.stale`, непустой `staleStarted` или `movedStarted`, `variants.unacceptable`). «Одинаково» стоит у каждого из нескольких вариантов с равной лучшей оценкой (поле `tied`), и «лучший» тогда не пишется ни у одного из них. На листе варианта цвет ячейки — как цвет подписей на карточке урока (`issues`, раздел 7.6): есть хоть одна проблема — красная; только некритичные подписи (`"level": "warn"`, например «В тот же день: …») — жёлтая. Под правилами на листе сравнения — блок «Кто ведёт» (`export.teacherRows`, заголовок `web.preview.teachers_head`): строка на каждый курс из `teacherCourses` (раздел 7.6), в ячейке варианта — имена из `teachers`. Если вариант сменит преподавателя курса (`teacherChanges`), ячейка залита жёлтым, а второй строкой в ней «Сейчас ведёт: …» (`web.preview.teacher_now`); нового преподавателя нет — первой строкой «без преподавателя» (`web.classes.no_teacher`). С этим блоком столбцы вариантов шире: в ячейках полные имена.

## 8. Версии

**Что копируется** (`versions.saveVersion`): `settings.json`, `weights.json`, `answer.json` (`versions.FILES`), только существующие, через `shutil.copy2`. **Варианты, метки вариантов и другие версии не копируются.**

**id версии** — время `ГГГГММДД-ччммсс`; если такая папка уже есть — `-2`, `-3`…

**`meta.json`:**

```json
{"name": "Передано руководителю",
 "comment": "Расписание из таблицы «Расписание и программы 26/27»",
 "created": "2026-10-04T01:19:31",
 "lessons": 116,
 "stages": ["1", "extra", "2"]}
```

- `name` пустое → `дд.мм.гггг чч:мм`; `newVersion` подставляет «Версия от …»;
- `lessons` — уроков в `answer.json` на момент сохранения (`versions.lessonCount`: без уроков курсов-копий);
- `stages` — `stages.acceptedStages` в тот момент.

`listVersions` пропускает папки без читаемого `meta.json` и сортирует по `created`, новые первыми.

**Виды версий:**
- **ручная** (`newVersion`);
- **«Перед: <действие>»** (`project.saveBeforeVersion`, текст `web.version.before`);
- **«Перед возвратом к версии от …»** — сохраняется автоматически перед `restore`; в `comment` — имя восстанавливаемой версии.

**Восстановление** (`tabs/save.restore` → `versions.restoreVersion`):
1. Проверка формата `settings.json` версии.
2. Сохранение текущего состояния версией.
3. Копирование файлов версии в проект. Файл, которого в версии нет, удаляется из проекта.
4. Удаление всей папки `stages/`.
5. `tree.prepareProject`.

**handover.** Версия с именем, равным переводу `web.save.handover_name` («Передано руководителю»), — исходное расписание, переданное вместе с программой. Её создаёт `tools/create_school_project.py`. В `state.versions[*]` у неё `handover: true`, и перед её удалением страница предупреждает особо. Признак определяется **только по имени**, отдельного поля в `meta.json` нет.

## 9. Совместимость

### 9.1. Что считается нарушением контракта

Нарушение — любое изменение, после которого уже сохранённые проекты, архивы или версии этой же программы читаются иначе или не читаются:

- переименование или удаление ключа, который кто-то читает (таблицы разделов 3–5), или смена его типа или смысла. Особенно опасны:
  - `"free"` = «не может»;
  - `"#"` = пустая ячейка;
  - `stream_id` = int, ключ этапа = строка;
  - `"день-урок"` в `constants`;
  - `{"number"}` / `{"numbers"}` в метках вариантов;
- смена правила, по которому строится название курса (`courses.courseName`), или ключ этапа (`model.stageKey`): это ключи во всех файлах;
- смена раскладки папки проекта: `stages/<этап>.variants/<N>.json`, `versions/<id>/meta.json`;
- смена формата архива: `settings.json` в корне zip;
- смена ключей `weights.json` без согласования шаблона, `METRICS`, `WEIGHT_ORDER` и `solve.cpp`;
- изменение входа или выхода движка без пересборки `solve.exe`. В папке может лежать **устаревший `solve.exe`**: после правки `solve.cpp` его нужно пересобрать (`compile.bat`), иначе Python и движок разойдутся;
- переименование действия (имя функции с `@action`) или его аргументов, адреса или поля ответа API. Страница и сервер поставляются вместе, но страница вызывает действия по имени, а `tests/test_structure.py` держит их список.

**Что не нарушает контракт:** добавить **необязательный** ключ, который читается через `.get(…, по умолчанию)`. Так уже живут `custom_penalties`, `block_dates`, `iterations`, `variants` и поле курса `together_with` (раздел 3.12). Если новый ключ нужен каждому проекту, достаточно добавить его в `tree.newProjectSettings`: `prepareProject` допишет его старым проектам при открытии (`setdefault`, только верхний уровень).

### 9.2. Как менять формат

Миграций нет и не будет.
1. Поднять `tree.PROJECT_FORMAT`.
2. Изменить `newProjectSettings` и код.
3. Старые проекты, архивы и версии программа откажется открывать с понятными сообщениями (`web.error.old_project`, `old_archive`, `old_version`). Файлы при этом не меняются.

Пользователь продолжает работать со старыми проектами в старой версии программы. Новый проект создаётся заново, например `tools/create_school_project.py` из исходной таблицы.

Временное правило для проектов без `format` (раздел 2) при этом стоит удалить заодно.
